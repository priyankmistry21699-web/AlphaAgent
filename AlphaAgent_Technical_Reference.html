Chapter 1 — System Overview & Philosophy

AlphaAgent is a multi-agent quantitative trading signal system that combines nine independent analytical perspectives into a single probability-scored trading recommendation. Every signal is produced through a rigorous, mathematically grounded pipeline with full transparency: every factor is scored 0–100, every agent reports its reasoning, and the orchestrator exposes the Bayesian posterior probability, Shannon entropy, and position-sizing multiplier to the end user.

Design Principles

  • No black boxes. Every factor that moves a probability is named, scored, and shown in the dashboard with its raw value and interpretation.
  • Correlation penalty. Agents that share data sources are penalized in the Bayesian fusion step so that correlated evidence is not double-counted.
  • Hard circuit breakers. The Risk Agent can override all other agents with a HALT command (position size = 0) when Black Swan, Flash Crash, or Hawkes cascade signals fire.
  • Dynamic confidence. Each agent passes a confidence weight (0–1) that scales its evidence in the Bayesian update; low-confidence agents contribute less.
  • Time-horizon awareness. The final probability blend is reweighted by a horizon multiplier map (1D→technical-dominant, 1Y→fundamental-dominant) before delivery to the user.

Signal Pipeline Summary

Step 1: MarketData fetches OHLCV, fundamentals, options, news, FRED macro in parallel (cached).
Step 2: 9 agents run in parallel via ThreadPoolExecutor. Each returns P(up) ∈ [0,1] + factor scores.
Step 3: Bayesian fusion combines agent probabilities with correlation penalties and confidence weights.
Step 4: Risk circuit breaker applies HALT / size-reduction overrides.
Step 5: HMM regime detection + signal decay half-life computed.
Step 6: Horizon reweighting applied per user-selected time frame.
Step 7: Final SignalPacket returned: direction, P(up), conviction %, entropy, size multiplier.

Chapter 5 — LangGraph Orchestrator

Node 1: data_ingestion_node

Pre-warms the MarketData cache. Calls get_ohlcv("1y"), get_financials(), get_info(), and fetches news. Because all results are cached in-process, subsequent agent calls to these methods return instantly from cache.

Node 2: run_agents_node

Uses Python's ThreadPoolExecutor with up to 9 workers to run all registered agents in parallel. Each agent gets its own thread. Results are collected via as_completed() futures. If any agent raises an exception, it is caught and replaced with a neutral AgentResult(probability_up=0.5).

Node 3: portfolio_manager_node

This is the aggregation brain. It performs six sequential operations:

  1. Risk circuit breaker check — reads Risk Agent reasoning text for keywords: CRITICAL RISK, BLACK SWAN, FLASH CRASH → sets multiplier = 0.0, direction = HOLD. HIGH RISK → multiplier = 0.5. GEO_SHOCK → multiplier ≤ 0.35.
  2. Bayesian fusion — feeds 8 agent probabilities (risk excluded) into BayesianFusion with correlation penalties. See Chapter 6.
  3. Direction assignment — P(up) > 0.55 → LONG, P(up) < 0.45 → SHORT, else HOLD.
  4. Conviction calculation — conviction = |P(up) − 0.5| × 2 (range: 0=neutral to 1=max).
  5. HMM regime detection — fits 3-state Gaussian HMM to 1-year returns. Labels current market as BULL/BEAR/CRISIS.
  6. Signal decay — estimates holding period via Ornstein-Uhlenbeck half-life of price reversion.

Chapter 6 — Bayesian Fusion Engine

Source: quant_engine/bayesian.py

Theory

Standard probability averaging ignores evidence strength and correlation. Bayesian Fusion operates in log-odds space where each agent's probability is converted to a log-odds (logit) and the contributions are summed — this is the correct Bayesian sequential update rule for independent evidence.

Mathematical Formulation

Initialization: \[ \text{LogOdds}_0 = \ln\!\left(\frac{\pi_0}{1 - \pi_0}\right) \] where \(\pi_0 = 0.5\) (uniform prior: no directional bias before evidence).

Evidence from agent \(i\): \[ E_i = \ln\!\left(\frac{p_i}{1 - p_i}\right) \cdot c_i \cdot (1 - \rho_i) \] where \(p_i\) = agent probability, \(c_i\) = confidence weight, \(\rho_i\) = correlation penalty.

Sequential update: \[ \text{LogOdds}_k = \text{LogOdds}_{k-1} + E_k \]
Posterior conversion (sigmoid): \[ P(\text{up}) = \frac{1}{1 + e^{-\text{LogOdds}_\text{final}}} \]

Shannon Entropy

\[ H = -\left[p \log_2 p + (1-p) \log_2(1-p)\right] \]
  • \(H = 0.0\): Perfect certainty (p = 0 or p = 1)
  • \(H = 1.0\): Total confusion (p = 0.5)
  • AlphaAgent warns when \(H > 0.9\): agents strongly disagree

Worked Example

Suppose technical agent reports p=0.72 (bullish) with confidence=0.9, no correlation. Macro agent reports p=0.48 (slightly bearish) with confidence=0.7, correlation=0.0. Sentiment reports p=0.65 with confidence=0.6, correlation=0.20.

Prior log-odds:     ln(0.5/0.5)    = 0.000
Technical:          ln(0.72/0.28) × 0.9 × 1.0 = 0.942 × 0.9 = +0.848
Macro:              ln(0.48/0.52) × 0.7 × 1.0 = −0.167 × 0.7 = −0.117
Sentiment:          ln(0.65/0.35) × 0.6 × 0.8 = 0.619 × 0.48 = +0.297
Final log-odds:     0.000 + 0.848 − 0.117 + 0.297 = 1.028
Posterior P(up):    1 / (1 + exp(−1.028)) = 0.736 → LONG

Chapter 7 — GARCH Volatility Model

Source: quant_engine/garch.py · Library: arch

Theory

GARCH (Generalized Autoregressive Conditional Heteroskedasticity) models the fact that financial volatility clusters — high-volatility days tend to follow high-volatility days. Unlike historical volatility which assumes constant vol, GARCH forecasts tomorrow's volatility based on recent shocks and the persistence of variance.

GARCH(1,1) Equation

Return equation: \[ r_t = \mu + \epsilon_t, \quad \epsilon_t = \sigma_t z_t, \quad z_t \sim N(0,1) \] Variance equation: \[ \sigma_t^2 = \omega + \alpha \epsilon_{t-1}^2 + \beta \sigma_{t-1}^2 \] Parameters:
  • \(\omega\) (omega): Long-run variance constant
  • \(\alpha\) (alpha[1]): News impact — how much last period's shock affects today's variance
  • \(\beta\) (beta[1]): Persistence — how much last period's variance persists today
Persistence: \(\alpha + \beta < 1\) for stationarity. Close to 1 = long memory.

Long-run (unconditional) volatility: \[ \sigma_\infty = \sqrt{\frac{\omega}{1 - \alpha - \beta}} \] Annualized from daily: \[ \sigma_\text{ann} = \sigma_\text{daily} \times \sqrt{252} \times 100 \]

Multi-Step Forecast

For horizon \(h\), GARCH variance forecast converges to the long-run variance: \[ \hat{\sigma}_{t+h}^2 = \sigma_\infty^2 + (\alpha+\beta)^{h-1}(\sigma_{t+1}^2 - \sigma_\infty^2) \] 5-day aggregated volatility: \[ \sigma_{5d} = \sqrt{\sum_{j=1}^{5} \hat{\sigma}_{t+j}^2} \]

Chapter 8 — Hidden Markov Model (Regime Detection)

Source: quant_engine/hmm.py · Library: hmmlearn

Theory

Markets cycle through unobservable (hidden) states — Bull, Bear, Crisis — which manifest as different return distributions. A Gaussian HMM learns these states unsupervised from return data: each state has a characteristic mean return and volatility. The model then assigns a probability to each state for the current period.

Model Specification

3-state Gaussian HMM: \[ P(r_t | S_t = k) = \mathcal{N}(\mu_k, \sigma_k^2) \] Transition matrix \(A\): \[ A_{ij} = P(S_t = j | S_{t-1} = i) \] State assignment: States are sorted by conditional volatility:
  • State 0 (lowest σ) → BULL regime
  • State 1 (medium σ) → BEAR regime
  • State 2 (highest σ) → CRISIS regime
Posterior probabilities via Forward-Backward algorithm: \[ \gamma_t(k) = P(S_t = k | r_1, \ldots, r_T) \]

Chapter 9 — Monte Carlo Simulation (GBM)

Source: quant_engine/monte_carlo.py

Geometric Brownian Motion

Continuous-time SDE: \[ dS = \mu S\,dt + \sigma S\,dW_t \] Discretized Euler-Maruyama (Itô form): \[ S_{t+1} = S_t \cdot \exp\!\left[\left(\mu - \frac{\sigma^2}{2}\right)\Delta t + \sigma\sqrt{\Delta t}\,Z_t\right] \] where \(Z_t \sim N(0,1)\), \(\Delta t = 1\) (daily), \(\mu\) = daily drift, \(\sigma\) = daily volatility. Why the \(-\sigma^2/2\) adjustment (Itô correction)? Without it, \(E[S_t]\) would be biased upward. The adjustment ensures \(E[S_T] = S_0 e^{\mu T}\).

Implementation (Vectorized)

# Generate all shocks at once: shape (days, num_paths)
Z = np.random.standard_normal((days, num_paths))
drift_adj = drift_daily - 0.5 * vol_daily**2
daily_returns = np.exp(drift_adj + vol_daily * Z)
cum_returns = np.cumprod(daily_returns, axis=0)   # Cumulative product per path
final_prices = current_price * cum_returns[-1, :] # Last day × num_paths

GARCH-Dynamic Version

Instead of constant vol, each day \(t\) uses GARCH-forecasted volatility \(\hat{\sigma}_t\):

for t in range(1, days + 1):
    vol_t = garch_forecasts[t-1]   # Day-specific GARCH forecast
    drift_adj = drift_daily - 0.5 * vol_t**2
    paths[t] = paths[t-1] * np.exp(drift_adj + vol_t * Z[t-1])

Chapter 10 — Quasi-Monte Carlo (Sobol Sequences)

Source: quant_engine/quasi_mc.py · Library: scipy.stats.qmc.Sobol

Why QMC?

Standard pseudorandom Monte Carlo converges at the probabilistic rate \(O(N^{-1/2})\). Quasi-random sequences (Sobol, Halton) use a structured low-discrepancy design that fills the sample space more uniformly, achieving the deterministic rate \(O((\log N)^d / N)\). In practice this means 10–100× tighter confidence intervals for the same number of paths.

Sobol Sequence Construction

Sobol sequences are based on Van der Corput sequences in base 2, extended to multi-dimensional spaces via direction numbers (Joe & Kuo 2003). Each dimension is a binary reflected Gray code sequence that minimizes the star discrepancy: \[ D^*_N = \sup_{[0,1]^d} \left| \frac{\#\{x_i \in B\}}{N} - \text{Vol}(B) \right| \] Implementation: scipy.stats.qmc.Sobol(d=days, scramble=True) generates an \((N \times d)\) uniform matrix which is then transformed via the inverse normal CDF to produce quasi-normal shocks: \[ Z_{ij} = \Phi^{-1}(u_{ij}), \quad u_{ij} \in \text{Sobol}(N, d) \]

Sobol sequences achieve maximum uniformity guarantees when the number of paths \(N\) is a power of 2. AlphaAgent automatically rounds up: _round_to_power2(n). Default: 4096 paths (= 2¹²).

Chapter 11 — Extreme Value Theory (EVT)

Source: quant_engine/evt.py · Libraries: scipy.stats.genpareto, scipy.stats.genextreme

Overview

Standard VaR assumes returns are normally distributed — but financial returns have fat tails. EVT focuses exclusively on the tail of the distribution using two rigorous approaches: Peaks-Over-Threshold (POT) with a Generalized Pareto Distribution, and Block Maxima with a Generalized Extreme Value distribution.

Method 1: POT — Generalized Pareto Distribution

Automatic threshold selection (Mean Excess Function): The optimal threshold \(u^*\) is selected where the Mean Excess Function \(e(u) = E[X - u | X > u]\) is most linear (low curvature), indicating the GPD assumption is valid. GPD fit: For exceedances \(y_i = x_i - u^*\) (losses above threshold): \[ P(Y \leq y) = 1 - \left(1 + \frac{\xi y}{\sigma}\right)^{-1/\xi} \] where \(\xi\) = shape (tail index), \(\sigma\) = scale. VaR formula (POT): \[ \text{VaR}_p = u^* + \frac{\sigma}{\xi}\left[\left(\frac{1-p}{\bar{F}(u^*)}\right)^{-\xi} - 1\right] \] CVaR (Expected Shortfall): \[ \text{CVaR}_p = \frac{\text{VaR}_p + \sigma - \xi u^*}{1 - \xi} \] Fat tail warning: If \(\xi > 0.5\), the variance is theoretically infinite. AlphaAgent warns: "Extremely fat tails — Black Swan risk."

Method 2: Block Maxima — GEV Distribution

Divide the return series into non-overlapping blocks of 21 trading days. Take the maximum loss in each block. Fit a Generalized Extreme Value (GEV) distribution: \[ P(M_n \leq x) = \exp\!\left[-\left(1 + \xi\frac{x-\mu}{\sigma}\right)^{-1/\xi}\right] \] GEV VaR: \[ \text{VaR}_p^{\text{GEV}} = \mu + \frac{\sigma}{\xi}\left[(-\log p)^{-\xi} - 1\right] \] GEV is used as a cross-check against the POT estimate. Divergence between the two signals model instability.

Tail Dependence Coefficient (\(\lambda_L\))

Measures the probability that the stock crashes given the market (SPY) crashes simultaneously. Uses an empirical (non-parametric) estimator: \[ \hat{\lambda}_L = \frac{\#\{X_t < Q_q(X) \text{ and } B_t < Q_q(B)\}}{\#\{B_t < Q_q(B)\}} \] where \(q = 0.05\) (worst 5% of market returns). Values near 1 mean the stock always crashes with the market. AlphaAgent warns when \(\lambda_L > 0.5\).

Chapter 12 — Kalman Filter (Dynamic Beta)

Source: quant_engine/kalman.py

Theory

Static OLS regression produces a single beta coefficient over the entire historical window. But betas change over time — a stock's sensitivity to the market shifts with macroeconomic regime, sector rotation, and company-specific events. The Kalman Filter treats beta as a latent state that evolves as a random walk and updates it optimally given new price data.

State-Space Formulation

State vector: \(\theta_t = [\alpha_t, \beta_t]^\top\) (intercept + slope) Observation equation: \[ r_{\text{stock},t} = \alpha_t + \beta_t \cdot r_{\text{SPY},t} + \epsilon_t, \quad \epsilon_t \sim N(0, R) \] State transition (random walk): \[ \theta_t = \theta_{t-1} + \eta_t, \quad \eta_t \sim N(0, Q) \] where \(Q = \frac{\delta}{1-\delta} I_2\) controls how quickly beta is allowed to change (\(\delta = 10^{-4}\) by default — slow drift).

Kalman Recursion

Predict: \[ \hat{\theta}_{t|t-1} = \theta_{t-1}, \quad P_{t|t-1} = P_{t-1} + Q \] Innovation: \[ \nu_t = r_{\text{stock},t} - H_t \hat{\theta}_{t|t-1}, \quad H_t = [1, r_{\text{SPY},t}] \] Kalman Gain: \[ K_t = P_{t|t-1} H_t^\top (H_t P_{t|t-1} H_t^\top + R)^{-1} \] Update: \[ \theta_t = \hat{\theta}_{t|t-1} + K_t \nu_t \] \[ P_t = (I - K_t H_t) P_{t|t-1} \]

Chapter 13 — Topological Data Analysis (TDA)

Source: quant_engine/tda_signal.py · Library: ripser (C++ persistent homology)

Theory

TDA applies algebraic topology to detect the "shape" of financial data that standard statistical measures miss. Persistent homology tracks how topological features (connected components = H0, loops = H1) appear and disappear as a filtration scale parameter grows. Long-lived features are "persistent" and considered genuine structure.

Pipeline

Step 1 — Takens Delay Embedding: Reconstruct a high-dimensional attractor from the 1D return series using delay coordinates: \[ \mathbf{x}_i = (r_i, r_{i+\tau}, r_{i+2\tau}, \ldots, r_{i+(d-1)\tau}) \in \mathbb{R}^d \] Default: \(d = 3\) (dimension), \(\tau = 2\) (lag). Normalized to \([0,1]^d\). Step 2 — Vietoris-Rips Complex: Build a simplicial complex by connecting points within distance \(\epsilon\). Grow \(\epsilon\) from 0 to max. Track birth and death of holes. Step 3 — Persistent Homology:
  • H0 barcodes: connected components (birth when cluster forms, death when merged)
  • H1 barcodes: loops (birth when loop forms, death when filled)
  • Lifetime = death − birth

Chapter 14 — Hawkes Self-Exciting Process

Source: quant_engine/hawkes.py

Theory

In a Hawkes process, each event increases the probability of further events — the process is self-exciting. In finance, a large price move (event) begets further large moves via informed trader responses, stop-loss cascades, and market maker hedging. A branching ratio approaching 1 signals that each event triggers nearly one child event — the process is explosive.

Exponential Hawkes Process

Conditional intensity: \[ \lambda(t) = \mu + \alpha \sum_{t_i < t} e^{-\beta(t - t_i)} \] Parameters:
  • \(\mu\) = background rate (baseline event frequency per day)
  • \(\alpha\) = excitation magnitude (each event's triggering strength)
  • \(\beta\) = decay rate (how fast excitement fades)
  • \(\alpha/\beta\) = branching ratio \(n\) (must be \(< 1\) for stationarity)
Event definition: Returns exceeding \(\pm 1.5\sigma\) (configurable) are extracted as events, converting the continuous return series to a point process \(\{t_1, t_2, \ldots, t_N\}\).

MLE Fitting (Ozaki 1979)

Log-likelihood: \[ \ell(\mu, \alpha, \beta) = \sum_{i=1}^N \log\lambda(t_i) - \int_0^T \lambda(t)\,dt \] Integral term (closed-form via recursion): \[ \int_0^T \lambda(t)\,dt = \mu T + \frac{\alpha}{\beta}\sum_{i=1}^N \left(1 - e^{-\beta(T-t_i)}\right) \] Recursive A_i (efficient computation): \[ A_i = e^{-\beta(t_i - t_{i-1})}(1 + A_{i-1}), \quad \lambda(t_i) = \mu + \alpha A_i \] Optimizer: SLSQP with constraint \(\beta > \alpha\) (guarantees branching ratio < 1 at convergence).

Cascade Risk Classification

Branching RatioLevelInterpretation
< 0.50LOWEvents rarely self-propagate. Normal market.
0.50–0.80MODERATESome clustering. Elevated HFT or informed trading.
0.80–0.95HIGHStrong clustering. Possible dark pool footprint or cascade start.
≥ 0.95CRITICALNear-explosive cascade. Institutional domino risk. Alert fired.

Dark Pool Signal

\[ \text{DarkPool} = \text{clip}\left(0.5 \cdot \frac{\alpha}{\beta} + 0.5 \cdot \text{clip}\left(\frac{(e/e_0 - 1)}{2}, 0, 1\right), 0, 1\right) \] where \(e\) = observed event rate, \(e_0 = 0.05\) (5% baseline). High clustering + above-average event rate suggests institutional block trading in dark pools.

Chapter 15 — Technical Agent (30 Factors)

Source: agents/technical.py · Agent name: "technical"

The Technical Agent analyzes price action, momentum, options flow, and market microstructure. It uses purely price- and options-derived signals — no fundamental or macro data. It is most predictive over 1–5 day horizons.

Factor Group 1 — Classical Technical Indicators

1. RSI — Relative Strength Index (14-period)
\[ \text{RSI} = 100 - \frac{100}{1 + \text{RS}}, \quad \text{RS} = \frac{\text{Avg Gain (14d)}}{\text{Avg Loss (14d)}} \]

Scoring: RSI < 30 → oversold → score ~80 (bullish). RSI > 70 → overbought → score ~20 (bearish). RSI 30–70 → score ~50 (neutral). Linear interpolation between thresholds.

Parameter: technical.rsi_window = 14 (dynamic, from settings.yaml)

2. MACD Histogram
\[ \text{MACD} = \text{EMA}_{12} - \text{EMA}_{26} \] \[ \text{Signal Line} = \text{EMA}_9(\text{MACD}) \] \[ \text{Histogram} = \text{MACD} - \text{Signal} \]

Scoring: Histogram > 0 and rising → score 70–80. Histogram < 0 and falling → score 20–30. Crossover events scored 75 (bullish cross) or 25 (bearish cross).

3. Bollinger Band Width (Squeeze Signal)
\[ \text{BB Width} = \frac{\text{Upper Band} - \text{Lower Band}}{\text{Middle Band}} \] \[ \text{Upper} = \text{SMA}_{20} + 2\sigma_{20}, \quad \text{Lower} = \text{SMA}_{20} - 2\sigma_{20} \]

Scoring: Narrow bands (squeeze) = compression → breakout expected → score 65. Wide bands (expansion) = already moving → score based on position within bands. Price above upper band → overbought → score 25.

Parameter: technical.bollinger_window = 20, technical.bollinger_std = 2.0

4. ADX — Average Directional Index
\[ \text{ADX} = \text{EMA}_{14}\!\left(\frac{|+\text{DI} - -\text{DI}|}{+\text{DI} + -\text{DI}} \times 100\right) \]

Scoring: ADX > 25 = strong trend → score 70–80 if price advancing, 30–20 if declining. ADX < 20 = weak/no trend → score ~50 (neutral). ADX measures trend strength, not direction.

5. Golden/Death Cross

SMA-50 vs SMA-200 crossover. If SMA-50 > SMA-200 → Golden Cross (bullish) → score 72. If SMA-50 < SMA-200 → Death Cross → score 28. If no crossover occurred → 55 (modest bullish/bearish depending on gap size).

6. EMA 9/21 Crossover

Fast EMA-9 vs slow EMA-21. If EMA-9 > EMA-21 → short-term bullish → score 65. If EMA-9 < EMA-21 → bearish → score 35. Crossover within 3 days → stronger signal ±10 points.

7. Momentum Acceleration
\[ \text{Mom} = \frac{P_t}{P_{t-22}} - 1, \quad \text{Accel} = \text{Mom}_{\text{recent}} - \text{Mom}_{\text{lagged}} \]

Scoring: Positive and accelerating momentum → score 70–85. Decelerating despite positive momentum → score drops toward 50. Negative and accelerating → score 15–30.

8. Variance Risk Premium (VRP)
\[ \text{VRP} = \text{IV}_{\text{ATM}} - \sigma_{\text{realized,30d}} \]

Positive VRP = options overpriced relative to realized vol = expected mean reversion. Score: VRP > 5% → bearish (score 35), VRP near 0 → neutral (50), VRP < −5% → options cheap, bullish (65).

Factor Group 2 — Options Microstructure

9. IV Skew (25Δ Put-Call)
\[ \text{IV Skew} = \text{IV}_{\text{OTM put}} - \text{IV}_{\text{OTM call}} \] \[ \text{OTM put}: K \in [0.85 \cdot S, 0.96 \cdot S] \quad \text{OTM call}: K \in [1.04 \cdot S, 1.15 \cdot S] \]

Interpretation: Positive skew = puts more expensive than calls = fear premium = market expects downside. Score: skew > 5% → score 30 (bearish). Skew < 0 → calls expensive → bullish/complacent → score 70. Near 0 → neutral 50.

10. Gamma Exposure (GEX)
Black-Scholes Gamma: \[ \Gamma = \frac{e^{-d_1^2/2}}{S \cdot \sigma \cdot \sqrt{T} \cdot \sqrt{2\pi}}, \quad d_1 = \frac{\ln(S/K) + (r + \frac{1}{2}\sigma^2)T}{\sigma\sqrt{T}} \] Net GEX ($ per 1% move): \[ \text{GEX} = \sum_i \Gamma_i^{\text{call}} \cdot \text{OI}_i^{\text{call}} \cdot 100 \cdot S - \sum_j \Gamma_j^{\text{put}} \cdot \text{OI}_j^{\text{put}} \cdot 100 \cdot S \]

Interpretation: Positive GEX → dealers long gamma → buy dips, sell rallies → volatility suppression → score 65. Negative GEX → dealers short gamma → amplify moves → score 35. Extreme negative GEX → potential pin risk → score 20.

11. Max Pain
\[ \text{MaxPain} = \arg\min_K \left[\sum_i \max(K - K_i, 0) \cdot \text{OI}_i^{\text{call}} + \sum_j \max(K_j - K, 0) \cdot \text{OI}_j^{\text{put}}\right] \]

Interpretation: Max pain is the strike where option holders lose the most money at expiration — market makers are said to push price toward this level. Gap = (MaxPain − Spot)/Spot × 100. Gap > 3% up → bullish (score 68). Gap > 3% down → bearish (score 32). Neutral within ±1% (score 50).

12. Implied Correlation (vs SPY)
\[ \text{Impl. Corr.} = \frac{\text{IV}_{\text{SPY,ATM}}}{\text{IV}_{\text{Stock,ATM}}} \]

Interpretation: Ratio > 1 = stock has lower implied vol than market → stock likely to move less than market → score 60. Ratio < 0.5 = stock implied vol much higher than market → idiosyncratic risk premium → score 35. Note: this is a proxy for the formal implied correlation basket formula.

Factor Group 3 — Signal Quality

13–14. TDA (Topological Data Analysis) Signal

See Chapter 13. The Technical Agent calls TDASignalEngine().analyze(prices) and adds the TDA signal as a factor. Score: 50 + tda_signal × 30 (range: 20 to 80). TRENDING regime → score 80. CYCLIC → score 20.

15–19. Additional Indicators (Stochastic, ATR, Trend Slope, Volume, CMF)

Stochastic Oscillator (%K/%D), ATR-normalized trend, 20-day volume z-score, Chaikin Money Flow, price position within 52-week range. All scored on the same 0–100 bullish/bearish scale.

30. PCA Signal Quality

Normalizes all factor scores to [−1,+1], computes mean signal direction, average signal strength, dispersion (std), and consensus as strength × max(0, 1 − dispersion/1.5). Score: 50 + consensus × 30. Low dispersion + strong direction → high quality signal (score 70–80). High dispersion + weak direction → poor quality signal (score 45–55).

\[ H = -\sum_i p_i \ln p_i \qquad H_\text{norm} = H / \ln N \qquad \text{score} = (1 - H_\text{norm}) \times 80 + 10 \]

Low entropy = all factors aligned (high conviction). High entropy = maximum internal disagreement.

\[ \text{upside\%} = \frac{\text{targetMeanPrice} - \text{currentPrice}}{\text{currentPrice}} \times 100 \]

>20% → score 85. >10%: prob_up += 0.04. <−10%: prob_up −= 0.04.

FRED series AAIIBULL and AAIIBEAR. Bull-bear spread <−20% → extreme bearishness → contrarian buy → score 75, prob_up += 0.04. Spread >30% → extreme bullishness → contrarian caution → score 25, prob_up −= 0.03.

Chapter 19 — Insider & Whale Agent

11 factors | Ticker: insider | EDGAR Form 4, Kyle's Lambda, cluster buying, institutional positioning

Architecture Overview

The Insider Agent detects "smart money" activity via SEC EDGAR Form 4 filings and institutional ownership data. Unlike other agents, final probability is derived as a mean of all factor scores (equal weighting, not additive update):

\[ \text{prob\_up} = \text{sigmoid-map}\!\left(\frac{1}{N}\sum_i \text{score}_i,\ [0,100]\right) \]

Factor 1 — Insider Sentiment (Net Transaction Volume)

From yfinance insider_transactions: net_shares = Σbuys − Σsells. Score maps net shares to 0–100 centered at 50. Confidence += 0.2 when |net_shares| > 50,000.

Factor 2 — Institutional Backing (Whale Sentiment)

From yfinance major_holders: institutional ownership %. >80% → high backing → score ~78. <30% → score ~35. Confidence += 0.2 when >80%.

Factor 3 — EDGAR Form 4 Activity Count

Form 4 filings (last 60 days) from SEC EDGAR. ≥5 → high cluster → score 65 (insiders buying ≥5 reports in 60 days is a statistically rare event). 0 → score 50. 1–4 → score 55.

Factor 4 — Material Events (8-K Count)

8-K filings in last 30 days. ≥5 → elevated material event risk → score 30, warning added. 1–4 → score 50. Earnings calls, executive changes, asset sales, and legal proceedings are all filed as 8-Ks.

Factor 5 — EDGAR Institutional Ownership (Cross-Check)

13F-based ownership from EDGAR. Score: min(80, edgar_inst_pct × 0.8). Cross-validates yfinance data with official SEC filings.

Factor 6 — Insider Cluster Buys

From yfinance insider_purchases: count buy transactions. Score: min(85, 40 + buy_count × 12). ≥3 transactions = "strong cluster" — multiple insiders buying simultaneously is one of the most reliable bullish microstructure signals.

Factor 7 — Institutional Ownership % (13F)

>70% → score 80. 40–70% → score 60. <40% → score 40. From yfinance institutional_holders.

Factor 8 — Short Squeeze Potential

\[ \text{squeeze\_score} = \min(85,\ 40 + \text{short\_float\%} \times 1.2) \]

>15% short float → "squeeze risk" warning. High short + rising price = self-reinforcing buying loop.

Factor 9 — Float Reduction (Buyback vs Dilution)

Quarterly balance sheet: share_chg = (shares_now − shares_old) / shares_old × 100. <−2% → active buyback → score 85. >+3% → dilution warning, score 20.

Factor 10 — Kyle's Lambda (Market Microstructure)

Theory (Kyle 1985)
\[ \Delta P_t = \lambda \cdot Q_t^{signed} + \varepsilon_t \qquad \hat{\lambda} = \frac{\text{Cov}(\Delta P,\ Q^{signed})}{\text{Var}(Q^{signed})} \]

λ = price impact per unit of signed order flow. High λ = thin market (large moves per share). Low λ = liquid (institutions can hide orders). Normalized: lambda_norm = |λ| × 10⁶ / avg_price. Score: clamp(70 − lambda_norm × 10, 10, 90).

Factor 11 — Insider Cluster 30-Day (EDGAR)

EDGAR Form 4 filings filed within the last 30 days. ≥3 filings in 30 days → strong recent cluster → score 75. More timely than the 60-day count in Factor 3.

Chapter 26 — Signal Decay & Holding Period (Ornstein-Uhlenbeck)

26.1 Holding Period Estimation

AlphaAgent estimates holding period using the Ornstein-Uhlenbeck mean-reversion half-life. If log-price follows an OU process, the half-life gives the expected time for a price deviation to revert 50% back to the mean — approximating the optimal holding period before alpha decays.

\[ dX_t = \theta(\mu - X_t)\,dt + \sigma\,dW_t \qquad t_{1/2} = \frac{\ln 2}{\theta} \]

The API response includes holding_period.min_days, expected_days, and max_days (68% confidence interval of the OU process).

30.1 Backtest Engine (backtest/engine.py)

Replays AlphaAgent signals on historical price data with realistic execution simulation.

ParameterDefaultDescription
initial_capital$100,000Starting portfolio cash
max_position_pct20%Max allocation per position
transaction_cost_bps5 bpsCommission (0.05% one-way)
bid_ask_spread_bps2 bpsSlippage
borrow_cost_annual0.50%Short selling borrow cost
kelly_fraction10%Kelly fraction for sizing
default_hold_days5Default exit horizon

Backtest Flow

  1. Download OHLCV for all tickers in backtest universe for the period.
  2. For each date: run orchestrator on data available up to that date only (no lookahead).
  3. Position sizing: kelly_fraction × |prob_up − 0.5| × 2 × max_position_pct.
  4. Cost model: buy at price × (1 + (transaction_cost + bid_ask)/10000). Sell symmetric. Short: deduct daily borrow.
  5. Exit: after default_hold_days or signal direction flip.
  6. Compute Sharpe, Sortino, max drawdown, win rate, profit factor, CAGR.
\[ \text{Sharpe} = \frac{R_p - R_f}{\sigma_p}\sqrt{252} \qquad \text{Sortino} = \frac{R_p - R_f}{\sigma_\text{down}}\sqrt{252} \] \[ \text{Max Drawdown} = \max_{t}\frac{\text{Peak}_{[0,t]} - \text{Trough}_{[t,T]}}{\text{Peak}_{[0,t]}} \qquad \text{Profit Factor} = \frac{\sum\text{wins}}{|\sum\text{losses}|} \]

30.2 Walk-Forward Validation (backtest/walk_forward.py)

Rolling windows prevent in-sample overfitting. Training period: 1 year (252 trading days). Test period: 3 months (63 trading days). Step: 1 month.

|─── Train (252d) ───|─ Test (63d) ─|
          |─── Train (252d) ───|─ Test (63d) ─|
                    |─── Train (252d) ───|─ Test (63d) ─|

Key metrics: OOS Sharpe, OOS win rate, Sharpe stability (std across windows). OOS win rate <50% → strategy is likely noise.
